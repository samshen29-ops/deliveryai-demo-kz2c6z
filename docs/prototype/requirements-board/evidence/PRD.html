1. 背景与目标

1.1 背景

Sam 空间-SDLC 需要用一个真实可交互的演示，串起 DeliveryAI 从需求澄清与原型、产品/技术 Spec、开发与自测、沙箱预览与冒烟、真实 E2E、代码评审与 PR，到人工发布决策的完整交付链。现有演示仓库是一个火锅点单 SPA，技术栈完整、无后端，但业务场景与 SDLC 无关。

本需求把该仓库复用于“研发需求与缺陷看板”演示：让评审者在一个中文单页应用里实际完成新增、校验、搜索筛选、状态流转、刷新持久化和证据查看，并能清楚区分合成演示数据、本轮真实产物与尚未执行的下游节点。

1.2 目标

目标衡量方式目标值 / 判断标准
可演示的需求/缺陷闭环AC-01..AC-11 在真实浏览器中可操作关键成功与失败路径均有可见结果
数据与统计可信卡片、计数、完成率、筛选结果一致每个筛选集合计数与卡片数一致；空集合不出现 NaN
状态规则可信合法流转成功、非法流转拒绝、完成后只读拒绝原因可解释并进入历史记录
持久化可信刷新后新增/编辑/合法流转保留损坏或不可用时给出受控提示，不静默删数据
证据不冒充示例记录、本轮真实产物、未执行项三类状态清晰不硬编码不存在的 PR、日志或 PASS
演示可复现一条命令启动、一份指南、一个复位入口评审者可在 5 分钟内按脚本完成演示

1.3 不做什么

  • 不接入后端 API、数据库、登录、权限、组织架构或真实用户体系。
  • 不做多人实时协作、评论、通知、附件上传、拖拽排序、批量导入导出。
  • 不接入 Jira、Meego、GitHub Issues 或其他外部缺陷/需求系统。
  • 不读取、写入或展示真实客户、员工、凭据、生产系统数据。
  • 不修改 main、不合并 PR、不启用 auto-merge、不公开发布、不更新既有 GitHub Pages 站点。
  • 不把原型预览、模拟流程动画或静态文案标记为“平台已执行成功”。
  • 不改变 Sam 空间-SDLC 的默认流程、默认 Agent、权限、集成与自动化。

4. 功能需求

REQ-001: 合成种子数据与状态覆盖

  • 优先级: P0
  • 用户价值: 评审者首次打开即可看到完整、可信的演示样本。
  • 需求描述: 系统首次打开或复位后展示 12 条合成工作项，覆盖待规划、进行中、审核中、阻塞中、已完成五种状态；每列至少 2 条，已完成 3 条；页面明确显示“演示合成数据”。
  • 验收标准 (EARS):
  • 当用户首次打开应用且本地无本应用数据时，系统应展示 12 条合成工作项、5 个状态分组和合成数据标识。
  • 当用户查看任意种子工作项时，系统应展示示例负责人名称（示例产品/示例研发/示例测试/示例设计），不得出现真实身份信息。
  • 当种子数据被筛选或搜索时，系统应只基于当前集合计算统计，不得改变种子数据本身。
  • Gherkin:
  Given 用户首次打开看板
  When 页面加载完成
  Then 应看到 12 张工作项卡片
  And 应看到待规划、进行中、审核中、阻塞中、已完成 5 个分组
  And 应看到“演示合成数据”标识

REQ-002: 新增工作项

  • 优先级: P0
  • 用户价值: 评审者能验证录入、校验与持久化的完整成功路径。
  • 需求描述: 用户可从主页打开新增对话框，填写类型、标题、描述、优先级、示例负责人、验收说明并保存；新工作项初始状态为待规划，创建后出现在看板与统计中。
  • 验收标准 (EARS):
  • 当用户提交合法表单时，系统应创建一条待规划工作项，关闭对话框，显示成功提示，并更新看板与统计。
  • 当用户点击取消、关闭按钮、按 Esc 或点击遮罩时，系统应关闭对话框且不创建、不修改任何数据。
  • 当用户再次打开新增对话框时，系统应展示空白表单或明确的默认值，不得残留上一次未保存内容。
  • Gherkin:
  Given 用户在新增工作项对话框
  When 填写合法标题并保存
  Then 看板应新增一张待规划卡片
  And 总数和待规划计数应各增加 1

REQ-003: 编辑工作项与取消

  • 优先级: P0
  • 用户价值: 评审者能验证修改保存与取消不产生副作用的差异。
  • 需求描述: 非已完成工作项可从详情抽屉进入编辑；保存后更新卡片、详情、统计与持久化；取消不保存任何改动。
  • 验收标准 (EARS):
  • 当用户编辑非已完成工作项并保存合法内容时，系统应更新对应字段并保留原状态、历史与证据。
  • 当用户取消编辑时，系统应丢弃本次表单改动，原数据保持不变。
  • 当工作项状态为已完成时，系统应隐藏或禁用编辑入口，并显示只读说明。
  • 反例: 已完成工作项不得因编辑而自动回到进行中；不得通过编辑绕过状态机。

REQ-004: 标题与描述校验

  • 优先级: P0
  • 用户价值: 防止空标题、超长内容和输入丢失。
  • 需求描述: 标题必填，保存前去除前后空格，按 Unicode 字符计长度 1-80；描述最多 2000 字符；错误应定位到字段并保留用户已输入内容。
  • 验收标准 (EARS):
  • 当标题去除前后空格后为空时，系统应拒绝保存，聚焦标题字段，并显示“标题不能为空”。
  • 当标题去除前后空格后超过 80 个字符时，系统应拒绝保存，显示当前字符数与上限，并保留输入。
  • 当描述超过 2000 个字符时，系统应拒绝保存，显示当前字符数与上限，并保留输入。
  • 当用户修正字段后，系统应清除对应错误并允许再次提交。
  • 边界: 仅空格标题视为空；标题前后空格不保存；描述可空；不把用户输入作为 HTML 执行。

REQ-005: 关键词搜索与组合筛选

  • 优先级: P0
  • 用户价值: 快速定位工作项并验证统计与卡片同源。
  • 需求描述: 支持标题/描述关键词搜索，以及类型、优先级、状态三个维度的组合筛选；维度内单选，维度间 AND；一键清空恢复全部数据。
  • 验收标准 (EARS):
  • 当用户输入关键词时，系统应只显示标题或描述包含该关键词的工作项；拉丁字符大小写不敏感，中文按子串匹配。
  • 当用户同时设置类型、优先级、状态时，系统应显示同时满足全部条件的工作项。
  • 当用户点击“清空筛选”时，系统应清空关键词与三个筛选器，恢复全部 12 条（或当前数据全集）。
  • 当筛选结果为空时，系统应显示解释性空态与“清空筛选”入口，不得只显示空白区域。
  • 反例: 不得把被筛掉的工作项计入当前统计；不得在清空筛选时删除数据。

REQ-006: 状态机与历史

  • 优先级: P0
  • 用户价值: 让状态规则可解释、可验证、不可静默越级。
  • 需求描述: 状态流转严格遵循：待规划→进行中；进行中→审核中或阻塞中；阻塞中→进行中；审核中→已完成或进行中；已完成无出边。非法流转拒绝，状态不变，并记录一条带原因的拒绝历史。
  • 验收标准 (EARS):
  • 当用户执行合法流转时，系统应更新状态、写入成功历史、刷新统计与卡片，并持久化。
  • 当用户尝试非法流转（跨级、逆向不允许、目标等于当前状态、从已完成流出）时，系统应拒绝，保持原状态，显示可解释原因，并写入拒绝历史。
  • 当工作项为已完成时，系统应只读展示，不提供可执行的状态流转或编辑入口，且不得自动重开。
  • 状态表:
当前状态允许目标拒绝示例
待规划进行中直接到审核中/阻塞中/已完成
进行中审核中、阻塞中直接到已完成、回到待规划
阻塞中进行中直接到审核中/已完成
审核中已完成、进行中直接到阻塞中、回到待规划
已完成无任何流转

REQ-007: 总览统计

  • 优先级: P0
  • 用户价值: 让评审者一眼看到当前筛选集合的规模与完成度。
  • 需求描述: 统计区展示当前筛选集合总数、五种状态数与完成率；完成率 = 已完成数 / 筛选集合总数；空集合显示“无数据”而不是 NaN 或 0%。
  • 验收标准 (EARS):
  • 当筛选集合非空时，系统应展示总数、各状态数和完成率，且与卡片数量一致。
  • 当筛选集合为空时，系统应展示总数 0、各状态 0、完成率“无数据”，不得出现 NaN、Infinity 或负数。
  • 当新增、编辑、流转或复位后，系统应立即重算统计。

REQ-008: 详情抽屉与证据类型

  • 优先级: P0
  • 用户价值: 让业务说明、验收、历史和证据在同一处可审。
  • 需求描述: 点击卡片打开详情抽屉，展示业务说明、验收清单、状态历史、证据清单和元数据；证据必须区分“示例记录”“本轮真实产物”“未执行/待确认”。
  • 验收标准 (EARS):
  • 当用户打开种子工作项详情时，系统应展示其业务说明、验收清单、状态历史和带“示例记录”标签的证据。
  • 当系统展示本轮真实产物时，应带“本轮真实产物”标签，并只展示实际存在的 PRD、原型或验收记录。
  • 当某项能力尚未执行时，系统应显示“未执行”或“待确认”，不得显示 PASS、成功日志、PR 链接或截图。
  • 当用户按 Esc 或点击关闭时，系统应关闭抽屉并把焦点返回触发卡片。

REQ-009: 持久化、损坏与不可用降级

  • 优先级: P0
  • 用户价值: 刷新不丢改动，异常时不静默损坏数据。
  • 需求描述: 新增、编辑、合法流转与复位写入本应用专属 localStorage key；加载时校验结构。数据损坏时保留原始内容并提示；localStorage 不可用或写入失败时降级为内存态。
  • 验收标准 (EARS):
  • 当用户完成新增、编辑或合法流转后刷新页面时，系统应恢复相同数据与状态。
  • 当本地数据无法解析或结构非法时，系统应展示受控提示，保留原始 key 内容不自动覆盖，并提供导出原始数据与显式覆盖入口。
  • 当 localStorage 不可用或写入失败时，系统应继续以内存态运行，显示“改动仅在本次页面保留”，不得抛出未处理错误或白屏。
  • 当用户未确认覆盖时，系统不得删除或改写未知/损坏数据。
  • 存储 key: sdlc-demo-board:v1。不得清空 i18nextLng、elderly-mode 或其他应用 key。

REQ-010: 演示复位

  • 优先级: P0
  • 用户价值: 让演示可重复，同时不误伤其他数据。
  • 需求描述: 演示复位仅重置本应用的合成数据，必须两步确认；取消不产生变化；复位不是产品空间、平台任务或 Git 的 reset。
  • 验收标准 (EARS):
  • 当用户点击复位并在第一步取消时，系统应不改变任何数据。
  • 当用户完成第二步确认时，系统应只重置本应用数据为 12 条种子，并保留其他 localStorage key。
  • 当 localStorage 不可用时，系统应仅重置内存态并提示刷新后可能丢失。
  • 反例: 不得调用 localStorage.clear()；不得删除工作区 artifacts/；不得触发平台 reset。

REQ-011: 能力证据与演示指南

  • 优先级: P0
  • 用户价值: 让评审者看到真实交付链，而不是模拟动画。
  • 需求描述: 提供“能力证据”和“如何演示”入口，按工作流节点展示实际产物与状态；本节点产物标记为已生成/待评审，下游未执行项标记为未执行/待确认。
  • 验收标准 (EARS):
  • 当用户打开能力证据时，系统应展示 7 个节点的名称、状态和可见产物说明。
  • 当某节点尚未执行时，系统应显示“未执行”或“待确认”，不得显示成功、PASS 或伪造链接。
  • 当用户打开如何演示时，系统应展示 5 分钟脚本，并说明授权边界与“原型不是公开发布”。

REQ-012: 安全、键盘与窄屏

  • 优先级: P0
  • 用户价值: 保证演示在评审环境可用且不引入安全风险。
  • 需求描述: 所有用户文本作为纯文本渲染；不执行 HTML/脚本；核心操作可键盘完成；390px 窄屏无核心内容遮挡；无本次引入的 console error；不包含真实凭据、身份或客户数据。
  • 验收标准 (EARS):
  • 当标题或描述包含 HTML/脚本片段时，系统应原样显示文本，不创建可执行元素、不触发脚本。
  • 当用户仅使用键盘时，系统应能打开新增、填写、保存、筛选、打开详情、执行流转、关闭弹层。
  • 当视口宽度为 390px 时，系统应保持核心内容可访问，不出现不可恢复的横向溢出或遮挡。
  • 当用户完成核心操作时，浏览器 console 不应出现本次引入的 error。

6. 数据结构与状态机

6.1 逻辑数据模型

type WorkItemType = 'requirement' | 'defect'
type Priority = 'P0' | 'P1' | 'P2' | 'P3'
type Status = '待规划' | '进行中' | '审核中' | '阻塞中' | '已完成'

interface WorkItem {
  id: string
  type: WorkItemType
  title: string
  description: string
  priority: Priority
  assignee: string
  acceptance: string
  status: Status
  createdAt: string
  updatedAt: string
  history: HistoryEvent[]
  evidence: Evidence[]
}

interface HistoryEvent {
  id: string
  at: string
  from: Status | null
  to: Status
  result: 'success' | 'rejected'
  reason: string
  actor: string
}

interface Evidence {
  id: string
  title: string
  kind: 'sample' | 'real' | 'pending'
  type: 'note' | 'doc' | 'test' | 'pr' | 'screenshot'
  status: string
  detail: string
}

interface BoardState {
  version: 1
  items: WorkItem[]
  updatedAt: string
}
  • version 不匹配、JSON 解析失败、items 非数组、必填字段缺失或枚举非法，均视为损坏数据。
  • 未知字段在可能的情况下保留，不因一次编辑静默丢弃整个对象。
  • 时间使用 ISO 8601 字符串，展示时按浏览器本地时区格式化。

6.2 状态机

待规划 --进行中--> 进行中
进行中 --审核中--> 审核中
进行中 --阻塞中--> 阻塞中
阻塞中 --进行中--> 进行中
审核中 --已完成--> 已完成
审核中 --进行中--> 进行中
已完成 --无--> 只读
  • 合法流转写入 result: success 历史。
  • 非法流转写入 result: rejected 历史，reason 必须包含当前状态、目标状态和允许目标；状态不变。
  • 新建工作项只能从待规划开始，表单不提供初始状态选择。
