# 产品 Spec: 研发需求与缺陷看板

> 本 Spec 把已评审 PRD 转成可开发、可测试、可追溯的产品契约。
> 它只约束用户可见行为、数据语义、状态规则和验收口径；具体文件拆分、函数签名和测试组织见同目录 Design 与 Test Plan。
> 本节点不落地实现代码，不创建 PR，不合并，不发布。AC-12 在本节点仍为部分覆盖。

## 0. 评审摘要

| 项目 | 内容 |
| --- | --- |
| 需求 | 在 Sam 空间-SDLC 的 GitHub 演示仓库中交付中文研发需求与缺陷看板，作为 SDLC 能力演示载体 |
| 需求类型 | 演示应用 / 前端单页应用 / 产品体验 |
| 基线 | `main` @ `1f47ad864fb9b97835cb8a453e6ed41d132f56e1`；工作分支 `demo/sam-sdlc-capability` @ `2ca14e0bcfb9e8273e75e31d67db71c0aacc6d7d` |
| 上游 | PRD v2 与交互原型已在“需求澄清与原型”节点通过用户评审（2026-11-27，无修改意见） |
| 本轮范围 | 产品 Spec、技术 Design、测试计划、AC 追溯；不实现、不跑真实 E2E、不建 PR |
| 关键决策 | 根地址默认进入看板 `#/board`；保留火锅演示 `#/home`；纯函数拆分；新增 Vitest 作为唯一新增开发依赖 |
| 阻塞项 | 无；待用户评审本 Spec 与 Design/Test Plan |
| AC-12 口径 | 仍为部分覆盖：PRD/原型/分支提交已完成；Spec/Design/Test Plan 本轮生成；实现、单测、构建、冒烟、真实 E2E、PR、审查未执行 |

### 0.1 与 PRD 的差异

本 Spec 不改变 PRD 的 AC-01..AC-12、状态规则、字段上限和授权边界。新增或细化如下：

1. 明确根地址 `/#/board` 为默认入口，`/#/home` 保留火锅演示；现有路由 E2E 需同步调整（见 REQ-013）。
2. 明确看板文案为中文单页，使用独立 `copy` 模块，不进入既有 zh/en i18n 双语资源。
3. 明确非法流转的演示方式：详情侧栏的目标状态下拉列出除当前状态外的全部状态，允许用户尝试并被拒绝，拒绝结果写入历史。
4. 明确统计完成率取整规则、筛选大小写规则、标题按 Unicode 码点计数规则。
5. 明确证据页使用构建期静态快照，不联网读取 PR/CI/平台状态，未执行项不得显示 PASS。

# 1. 背景与目标

## 1.1 背景

Sam 空间-SDLC 需要用真实可交互的演示串起 DeliveryAI 从需求澄清与原型、产品/技术 Spec、开发与自测、沙箱预览与冒烟、真实 E2E、代码评审与 PR，到人工发布决策的完整链路。现有仓库 `samshen29-ops/deliveryai-demo-kz2c6z` 是一个无后端的 React 18 火锅点单 SPA，技术栈和测试框架完整，但业务场景与 SDLC 无关。

上游节点已交付并评审通过中文看板 PRD 与独立静态原型。本节点要把原型行为固化为可开发契约，避免开发阶段在路由、校验、统计、状态机、持久化和证据真实性上产生分叉。

## 1.2 目标

| 目标 | 衡量方式 | 目标值 / 判断标准 |
| --- | --- | --- |
| 行为契约完整 | 每个 AC 都有 REQ、判定口径、反例和下游测试 ID | AC-01..AC-12 全部可追溯到测试计划 |
| 数据与统计一致 | 同一筛选集合驱动卡片、列计数、顶部统计和完成率 | 计数不一致即为缺陷；空集合不出现 NaN/Infinity |
| 状态规则可解释 | 合法流转写成功历史，非法流转写拒绝历史且状态不变 | 25 个状态对组合全部有明确结果 |
| 持久化不静默损坏 | 刷新保留合法改动；损坏/不可用时受控提示 | 不调用 `localStorage.clear()`，不改其他 key |
| 证据不冒充 | 示例记录、真实产物、未执行项三类标签清晰 | 未执行项不出现 PASS、PR 链接或成功日志 |
| 实现可验证 | 纯函数单测 + 真实浏览器 E2E + 构建/静态检查 | 每项 AC 至少有 1 条可执行验证；0 测试/全跳过/超时不记 PASS |

## 1.3 不做什么

- 不接入后端 API、数据库、登录、权限、组织架构、真实用户或客户数据。
- 不做多人实时协作、评论、通知、附件上传、拖拽排序、批量导入导出、跨标签页同步。
- 不接入 Jira、Meego、GitHub Issues 等外部需求/缺陷系统。
- 不修改 `main`、不合并 PR、不启用 auto-merge、不公开发布、不更新现有 GitHub Pages。
- 不创建新的收费资源，不操作生产系统，不改变空间默认流程、默认 Agent、权限、集成与自动化。
- 不把原型预览、静态证据页或模拟动画标记为“平台已执行成功”。
- 不在本节点写实现代码、提交实现或创建 PR。

# 3. 范围与信息架构

## 3.1 产品形态

- 中文单页看板，桌面与 390px 窄屏可用；复用仓库 React 18 + TypeScript + Vite + Tailwind CSS、Radix Dialog、lucide-react 与既有色板。
- 无后端；数据存于浏览器 `localStorage` 的本应用专属 key。
- 看板是以 `#/board` 为入口的独立视图壳；火锅演示继续使用既有 `#/home`、`#/menu` 等路由。
- 视觉基线采用仓库 `tailwind.config.js` 的 rice/chili/amber/charcoal 色板、Inter/Noto Sans SC 字体栈、圆角与阴影；`knowledge/design-system/` 为空，不引入外部设计系统。

## 3.2 页面与入口

| 页面 / 区域 | 路由 / 入口 | 内容 | 主要操作 |
| --- | --- | --- | --- |
| 看板主页 | `#/board`，根地址默认进入 | 合成数据标识、统计、搜索筛选、5 列状态看板、空态、顶部导航 | 新增、搜索、筛选、清空、打开详情、复位、进入能力证据/如何演示 |
| 工作项详情侧栏 | 看板内弹层 | 业务说明、验收清单、状态流转、状态历史、证据清单、元数据 | 编辑、合法/非法流转、关闭 |
| 新增/编辑对话框 | 看板内弹层 | 类型、标题、描述、优先级、示例负责人、验收说明 | 保存、取消、Esc/遮罩关闭 |
| 能力证据 | 看板内视图（`#/board` 下切换） | 7 个节点状态、产物入口、AC 追溯 | 查看产物、识别未执行项 |
| 如何演示 | 看板内视图 | 5 分钟脚本、四角色、边界说明 | 按步骤演示 |
| 演示复位 | 看板内两步对话框 | 作用范围、二次确认 | 取消、继续、确认 |
| 火锅演示入口 | `#/home` | 既有火锅点单首页 | 从看板侧栏进入；火锅首页提供返回看板入口 |

> 看板内部的能力证据/如何演示是视图状态，不新增顶层路由，避免与既有 hash 路由和浏览器历史冲突；刷新后回到看板主页。

## 3.3 全局标识

- 看板固定展示 `演示合成数据` 标识，示例负责人只使用 `示例产品`、`示例研发`、`示例测试`、`示例设计`。
- 合成数据条固定说明：“本页状态来自工作区实际产物，不是平台运行结果；未执行项不会标记为成功。”
- 证据标签固定为三类：`示例记录`、`本轮真实产物`、`未执行` / `待确认`。
- 任何页面不得出现真实姓名、邮箱、手机号、token、Cookie、私钥、密码、完整连接串或客户数据。

# 4. 功能需求

> 每条需求给出用户价值、行为契约、EARS 验收与反例。测试用例编号见 Test Plan；本节点只定义，不执行。

## REQ-001: 合成种子数据与状态覆盖（AC-01）

- **优先级**：P0
- **用户价值**：评审者首次打开即可看到完整、可信、可筛选的演示样本。
- **行为契约**：
  - 首次打开（本应用 key 不存在）或演示复位后，展示 12 条合成工作项。
  - 状态分布固定为：待规划 2、进行中 3、审核中 2、阻塞中 2、已完成 3；完成率 25%。
  - 每条种子包含：`id`、`type`、`title`、`description`、`priority`、`assignee`、`acceptance`、`status`、`createdAt`、`updatedAt`、`history`、`evidence`。
  - 至少 1 条 `requirement` 和 1 条 `defect`；每条至少 1 条 `sample` 证据和 1 条成功历史。
  - 种子内容以原型 `seedItems()`（提交 `2ca14e0`）为准，迁移时逐字复制标题、描述、验收与示例证据；仅允许修正原型中的错别字，不允许改写业务语义。
- **EARS**：
  - 当用户首次打开看板且本应用 key 不存在时，系统应展示 12 张工作项卡片、5 个状态分组和“演示合成数据”标识。
  - 当用户查看种子详情时，系统应展示示例负责人、业务说明、验收清单、状态历史和至少 1 条带“示例记录”标签的证据。
  - 当用户筛选或搜索时，系统应只改变可见集合与统计，不得修改种子数据本身。
  - 如果本应用 key 存在且合法，系统应加载已保存数据而不是种子。
- **反例**：种子数量不是 12；某列少于 2 条；已完成不是 3 条；出现真实姓名；首次打开因存储异常白屏。

## REQ-002: 新增工作项（AC-02）

- **优先级**：P0
- **行为契约**：
  - 新增表单字段：类型（需求/缺陷，默认需求）、标题、描述、优先级（P0-P3，默认 P2）、示例负责人（默认示例产品）、验收说明。
  - 保存合法表单后创建 1 条 `待规划` 工作项，ID 为 `DEMO-<当前最大数字+1>`（无 DEMO 项时从 101 开始），写入创建历史，插入列表首位，打开详情，显示成功提示。
  - 新工作项证据包含 1 条 `sample` 记录，说明“本页创建的演示工作项，不是真实业务记录”。
  - 取消（按钮、关闭图标、Esc、点击遮罩）不写入任何数据；再次打开为空白/默认值，不残留上次输入。
- **EARS**：
  - 当用户提交合法表单时，系统应创建待规划工作项、关闭对话框、更新看板与统计并持久化。
  - 当用户取消新增时，系统应关闭对话框且不创建、不修改任何数据。
  - 当用户再次打开新增表单时，系统应展示默认值，不残留上次未保存内容。
- **反例**：新工作项直接进入进行中；ID 重复；取消后统计变化；保存后刷新丢失。

## REQ-003: 编辑工作项与取消（AC-02）

- **优先级**：P0
- **行为契约**：
  - 非已完成工作项可从详情侧栏进入编辑；保存后更新类型、标题、描述、优先级、示例负责人、验收说明与 `updatedAt`，保留 `status`、`history`、`evidence`、`createdAt`、`id`。
  - 编辑表单不提供状态字段，不能通过编辑绕过状态机。
  - 取消编辑丢弃本次改动，原数据、统计和持久化均不变。
  - 已完成工作项不显示编辑入口，显示只读说明。
- **EARS**：
  - 当用户保存合法编辑时，系统应更新对应字段并保留状态、历史与证据。
  - 当用户取消编辑时，系统应丢弃改动且不写入存储。
  - 当工作项为已完成时，系统应隐藏编辑与流转入口，并显示“已完成，只读”。
- **反例**：编辑把已完成改回进行中；编辑重置历史；取消仍写入 `updatedAt`。

## REQ-004: 标题、描述与验收校验（AC-03）

- **优先级**：P0
- **行为契约**：
  - 标题保存前去除首尾空白；按 Unicode 码点计数（`Array.from(str).length`），长度必须为 1-80。
  - 描述可空，最多 2000 个 Unicode 码点。
  - 验收说明可空，最多 2000 个 Unicode 码点；非空时每行（去除首尾空白后）作为一条验收清单。
  - 类型、优先级、示例负责人必须是枚举值；非法值拒绝保存。
  - 错误必须：字段级可见、`aria-invalid="true"`、错误文案包含当前长度与上限（超长时）、聚焦第一个错误字段、保留全部已输入内容。
  - 错误文案固定：
    - 空标题：`标题不能为空。`
    - 超长标题：`标题最多 80 个字符，当前 N 个。`
    - 超长描述：`描述最多 2000 个字符，当前 N 个。`
    - 超长验收：`验收说明最多 2000 个字符，当前 N 个。`
    - 枚举非法：`请选择需求或缺陷。` / `请选择合法优先级。` / `请选择示例负责人。`
- **EARS**：
  - 当标题去除首尾空格后为空时，系统应拒绝保存、聚焦标题并显示“标题不能为空”。
  - 当标题为 81 个 Unicode 码点时，系统应拒绝保存并显示当前长度。
  - 当描述或验收为 2001 个码点时，系统应拒绝保存并显示当前长度。
  - 当用户修正字段后，系统应清除对应错误并允许再次提交。
  - 当标题前后有空格时，系统应保存去除首尾空格后的值。
- **反例**：仅空格标题被接受；用 `String.length` 把 emoji 算成 2；超长时清空输入；错误只显示在顶部 Toast 而无字段定位。

## REQ-005: 关键词搜索与组合筛选（AC-04）

- **优先级**：P0
- **行为契约**：
  - 关键词：对 `title` 和 `description` 做子串匹配；先 `trim()`，再用 `toLocaleLowerCase('zh-CN')` 归一化；拉丁字符大小写不敏感，中文按子串匹配；不搜索验收说明、负责人、ID 或证据。
  - 类型、优先级、状态：维度内单选（含“全部”）；维度间 AND；与关键词 AND。
  - 一键清空：清空关键词与三个筛选器，恢复当前数据全集（通常 12 条），不删除数据、不改存储。
  - 空结果：显示解释性空态、当前筛选摘要和“清空筛选”入口；不得只留空白。
  - 筛选状态为内存态，不持久化；刷新后回到未筛选。
- **EARS**：
  - 当用户输入关键词时，系统应只显示标题或描述包含该关键词的工作项。
  - 当用户同时设置类型、优先级、状态时，系统应显示同时满足全部条件的工作项。
  - 当用户点击“清空筛选”时，系统应恢复当前数据全集并清空摘要。
  - 当结果为 0 时，系统应显示空态解释与清空入口。
- **反例**：筛选后统计仍按全量计算；清空筛选删除数据；关键词匹配验收说明；空白关键词被当作筛选条件。

## REQ-006: 状态机、历史与只读（AC-05）

- **优先级**：P0
- **行为契约**：
  - 状态集合：`待规划`、`进行中`、`审核中`、`阻塞中`、`已完成`。
  - 允许流转：待规划→进行中；进行中→审核中/阻塞中；阻塞中→进行中；审核中→已完成/进行中；已完成无出边。
  - 合法流转：更新状态与 `updatedAt`，在历史头部写入 `result: success` 事件，持久化，刷新统计与卡片，显示“已流转到「X」”。
  - 非法流转：状态不变，在历史头部写入 `result: rejected` 事件，`reason` 必须包含当前状态、目标状态和允许目标；显示可解释错误；持久化拒绝历史。
  - 目标等于当前状态视为非法，写入拒绝历史。
  - 已完成：不显示编辑与流转控件，显示只读说明；不得自动重开。若通过过期 UI/程序化调用尝试流转，仍按非法处理并写拒绝历史。
  - 详情侧栏的目标状态下拉列出除当前状态外的全部状态（允许项优先，可标注“允许”），以便演示非法流转被拒绝；已完成无下拉。
- **EARS**：
  - 当用户执行合法流转时，系统应更新状态、写入成功历史、刷新统计并持久化。
  - 当用户执行非法流转时，系统应拒绝、保持状态、显示原因并写入拒绝历史。
  - 当工作项为已完成时，系统应只读展示，不提供编辑或流转入口。
- **反例**：跨级直接完成；阻塞中直接完成；审核中回到待规划；拒绝只弹 Toast 不写历史；已完成自动重开。

## REQ-007: 总览统计（AC-07）

- **优先级**：P0
- **行为契约**：
  - 统计集合 = 当前关键词 + 类型 + 优先级 + 状态筛选后的集合。
  - 总数 = 集合长度；各状态数 = 集合内该状态卡片数；列计数使用同一集合。
  - 完成率 = `Math.round(已完成数 / 总数 * 100)`，展示为整数百分比；例如 1/3 显示 33%，3/12 显示 25%。
  - 总数为 0 时：总数 0、各状态 0、完成率显示 `无数据`，状态占比显示 `无数据`；不得出现 `NaN`、`Infinity`、负数或 `0%` 冒充无数据。
  - 新增、编辑、流转、复位后立即重算。
- **EARS**：
  - 当筛选集合非空时，系统应展示总数、各状态数和完成率，且与卡片数量一致。
  - 当筛选集合为空时，系统应展示 0 计数和“无数据”完成率。
  - 当数据变化时，系统应在同一渲染周期内重算统计。
- **反例**：列计数与卡片不一致；完成率用全量分母；空集合显示 `NaN%`；四舍五入规则不一致。

## REQ-008: 详情侧栏与证据类型（AC-08）

- **优先级**：P0
- **行为契约**：
  - 点击卡片打开右侧详情侧栏，展示：ID、标题、类型、优先级、状态、负责人、业务说明、验收清单、状态流转、状态历史（按时间倒序，同时间保持数组顺序）、证据清单、元数据（创建/更新时间、数据性质）。
  - 证据按 `kind` 分组/标注：`sample` → `示例记录`；`real` → `本轮真实产物`；`pending` → `未执行`/`待确认`。
  - 全局“本轮真实产物”区只列实际存在的 PRD、Spec、原型、测试报告等；未执行项显示 `未执行`/`待确认`，不得显示 PASS、虚构 PR、执行日志或截图。
  - 示例证据不得带真实链接、真实 commit、真实 PR 号或“PASS”字样。
  - 按 Esc、点击关闭或遮罩关闭，焦点返回触发卡片。
- **EARS**：
  - 当用户打开种子详情时，系统应展示业务说明、验收清单、历史与示例证据。
  - 当系统展示本轮真实产物时，应只展示实际存在的产物并带对应标签。
  - 当能力未执行时，系统应显示“未执行”或“待确认”，不得显示成功状态。
  - 当用户关闭侧栏时，系统应把焦点返回触发卡片。
- **反例**：所有证据混在一起无标签；示例证据出现真实 PR 链接；未执行 E2E 显示 PASS；关闭后焦点丢失。

## REQ-009: 持久化、损坏与不可用降级（AC-06）

- **优先级**：P0
- **行为契约**：
  - 存储 key 固定为 `sdlc-demo-board:v1`；只读写该 key，不调用 `localStorage.clear()`，不修改 `i18nextLng`、`elderly-mode` 或其他 key。
  - 保存时机：新增、编辑、合法流转、非法流转（拒绝历史）、复位、显式覆盖。筛选不持久化。
  - 加载校验：顶层为对象、`version === 1`、`items` 为数组、每条必填字符串字段齐全、枚举合法、ID 唯一、`history`/`evidence` 为数组且事件/证据结构合法。
  - 损坏（JSON 解析失败或结构非法）：使用种子在内存中运行，展示受控警告，保留原始 raw 内容，提供“导出原始数据”和“用当前数据覆盖”；用户确认前不得覆盖或删除原始内容。
  - 不可用（访问/写入抛错）：以内存态运行，展示“改动仅在本次页面保留”，不白屏、不抛出未处理错误；提供“重试保存”。
  - 写入失败（配额/权限）：保留当前内存态，展示错误与重试入口；不得静默丢弃。
  - 未知字段：加载时保留原始对象中的未知顶层字段与工作项字段，保存时尽量回写，不因一次编辑丢弃。
- **EARS**：
  - 当用户完成新增、编辑或合法流转后刷新时，系统应恢复相同数据与状态。
  - 当本地数据损坏时，系统应展示警告、保留原始内容并提供导出/显式覆盖。
  - 当 localStorage 不可用时，系统应继续以内存态运行并提示刷新后可能丢失。
  - 当用户未确认覆盖时，系统不得改写损坏的原始内容。
- **反例**：损坏时直接用种子覆盖；读取失败白屏；保存失败仍提示成功；调用 `localStorage.clear()` 清掉其他 key。

## REQ-010: 演示复位（AC-09）

- **优先级**：P0
- **行为契约**：
  - 两步确认：第 1 步说明只重置本应用 key 为 12 条种子、不影响其他 key/产物/Git；第 2 步再次确认“确认重置本应用数据”。
  - 任一步取消、Esc、点击遮罩均不改变数据、筛选、详情或存储。
  - 确认后：重置为 12 条种子，清空筛选，关闭详情，写入本应用 key，显示“已恢复 12 条演示数据；其他 localStorage key 未改动。”
  - 存储不可用时仅重置内存态，并提示刷新后可能丢失；仍不得删除其他 key。
  - 复位不是产品空间、平台任务或 Git 的 reset。
- **EARS**：
  - 当用户在任一步取消时，系统应保持现状不变。
  - 当用户完成第二步确认时，系统应只重置本应用 key 并保留其他 key。
  - 当存储不可用时，系统应只重置内存态并提示。
- **反例**：单击即重置；复位清空整个 localStorage；复位触发平台 reset；复位删除工作区 artifacts。

## REQ-011: 能力证据与演示指南（AC-08、AC-12）

- **优先级**：P0
- **行为契约**：
  - 能力证据展示 7 个节点：需求澄清与原型、产品与技术 Spec、开发/自测与用例、沙箱预览与冒烟、真实 E2E 与证据、代码评审与 PR、人工发布决策。
  - 节点状态只能来自构建期静态快照：`已通过`、`已生成 · 待评审`、`已执行`、`未执行`、`未创建`、`待确认`。
  - 本节点（Spec）状态为 `已生成 · 待评审`，不得显示 `已通过`；后续节点显示 `未执行`/`未创建`/`待确认`。
  - 产物入口只链接仓库内实际存在的文件（PRD、Spec、Design、Test Plan、原型说明），不链接虚构 PR/CI/部署。
  - 如何演示展示 5 分钟脚本、四角色分工、授权边界、合成数据与“不是公开发布”说明。
- **EARS**：
  - 当用户打开能力证据时，系统应展示 7 个节点、状态和实际产物入口。
  - 当节点未执行时，系统应显示“未执行/待确认”，不得显示 PASS。
  - 当用户打开如何演示时，系统应展示 5 分钟脚本与边界说明。
- **反例**：把原型预览标为正式冒烟；Spec 未评审却显示已通过；显示不存在的 PR 号；用动画冒充平台运行结果。

## REQ-012: 安全、键盘、窄屏与可观测性（AC-10、AC-11）

- **优先级**：P0
- **行为契约**：
  - 所有用户输入按纯文本渲染；不使用 `dangerouslySetInnerHTML`、`innerHTML`、`eval` 或动态脚本注入；HTML/脚本片段只作为可见文本。
  - 不包含真实凭据、身份、客户数据；不发起新的外部网络请求；证据链接仅指向仓库内静态文件。
  - 核心操作可仅用键盘完成：打开新增、填写、保存、搜索、筛选、清空、打开详情、执行流转、关闭弹层。
  - 可见焦点环；表单 `label` 与错误 `aria-describedby` 关联；对话框焦点陷阱与 Esc 关闭；Toast `role="status"`/`aria-live="polite"`；错误 `role="alert"`。
  - 1440px 桌面 5 列同屏；390px 窄屏页面本身不横向溢出，看板列在容器内横向滚动，筛选栏换行，详情侧栏/表单不超宽。
  - 核心操作过程中不产生本次引入的 console error；允许既有字体加载失败等环境噪声，但需在报告中记录。
- **EARS**：
  - 当标题或描述包含 HTML/脚本时，系统应原样显示文本且不执行。
  - 当用户仅用键盘时，系统应完成新增、筛选、详情、流转和关闭。
  - 当视口为 390px 时，系统应保持核心内容可访问且无页面级横向溢出。
  - 当用户完成核心操作时，console 不应出现本次引入的 error。
- **反例**：用 `dangerouslySetInnerHTML` 渲染描述；脚本执行；窄屏页面横向滚动导致列不可达；键盘无法关闭弹层；console 报错被忽略。

# 5. 产品规则

## 5.1 字段与校验

| 字段 | 类型 | 必填 | 默认 | 规则 | 位置 |
| --- | --- | --- | --- | --- | --- |
| `id` | string | 是 | 自动 | `DEMO-<n>`；全局唯一；新建取最大数字+1 | 卡片、详情、存储 |
| `type` | `requirement \| defect` | 是 | `requirement` | 枚举；展示为“需求/缺陷” | 表单、卡片、详情、筛选 |
| `title` | string | 是 | 空 | 去首尾空白；Unicode 码点 1-80 | 表单、卡片、详情、搜索 |
| `description` | string | 否 | 空 | 最多 2000 码点；纯文本；搜索 | 表单、卡片摘要、详情 |
| `priority` | `P0 \| P1 \| P2 \| P3` | 是 | `P2` | 枚举 | 表单、卡片、详情、筛选 |
| `assignee` | enum | 是 | `示例产品` | `示例产品/示例研发/示例测试/示例设计` | 表单、卡片、详情 |
| `acceptance` | string | 否 | 空 | 最多 2000 码点；每行一条清单 | 表单、详情 |
| `status` | enum | 是 | `待规划` | 五状态；受状态机约束；新建不可选 | 列、详情、筛选 |
| `createdAt` | ISO string | 是 | 当前时间 | 创建后不变 | 详情、存储 |
| `updatedAt` | ISO string | 是 | 当前时间 | 任意数据变更时更新 | 详情、存储 |
| `history` | HistoryEvent[] | 是 | 创建事件 | 新事件插入头部；含成功/拒绝 | 详情、存储 |
| `evidence` | Evidence[] | 是 | 示例记录 | 每条含 `kind/title/detail/type/status` | 详情、存储 |

## 5.2 状态与反馈

| 场景 | 用户可见反馈 | 数据影响 |
| --- | --- | --- |
| 新增成功 | Toast“已新增待规划工作项。”+ 新卡片 + 打开详情 | 新增 1 条待规划 |
| 编辑成功 | Toast“已保存修改。”+ 详情更新 | 更新字段，保留状态/历史/证据 |
| 取消编辑 | 对话框关闭，无持久化 | 无变化 |
| 合法流转 | Toast“已流转到「X」。”+ 成功历史 | 状态更新 + 历史 |
| 非法流转 | 侧栏红色提示 + Toast“流转被拒绝：…”+ 拒绝历史 | 状态不变 + 历史 |
| 空筛选 | 空态说明 + 清空按钮 | 无变化 |
| 存储损坏 | 警告条 + 导出原始数据 + 显式覆盖 | 原始 raw 保留 |
| 存储不可用/写入失败 | 警告条 + 重试保存 | 内存态 |
| 复位取消 | 关闭对话框 | 无变化 |
| 复位确认 | Toast“已恢复 12 条演示数据；其他 localStorage key 未改动。” | 仅本应用 key 重置 |

## 5.3 统计规则

- 统计集合与卡片集合必须是同一个 `filteredItems`，不得分别计算。
- 列计数 = 该列在当前集合中的条数；顶部总数 = 当前集合长度。
- 完成率 = `Math.round(completed / total * 100)`；空集合返回 `null`，UI 显示“无数据”。
- 状态占比 = `total ? Math.round(count / total * 100) : null`；空集合显示“无数据”。
- 完成率进度条宽度在 0-100 之间；空集合宽度 0。

## 5.4 证据规则

| 类型 | 标签 | 允许内容 | 禁止内容 |
| --- | --- | --- | --- |
| `sample` | 示例记录 | 合成需求说明、示例验收、示例测试备注 | 真实 PR、真实 commit、真实执行日志、PASS |
| `real` | 本轮真实产物 | 本轮实际存在的 PRD/Spec/Design/Test Plan/原型/测试报告/截图 | 未生成却声称存在 |
| `pending` | 未执行 / 待确认 | 下游节点、未运行测试、未创建 PR、未决策发布 | 伪造成功、PASS、虚构链接 |

- `real` 证据必须由构建期常量提供，包含可核对的仓库相对路径；不得在运行时抓取网络或平台 API。
- 证据页的“已执行”必须有报告路径、命令、退出码或截图支撑；否则只能标“未执行/待确认”。

# 6. 数据结构与状态机

## 6.1 逻辑数据模型

```ts
export type WorkItemType = 'requirement' | 'defect'
export type Priority = 'P0' | 'P1' | 'P2' | 'P3'
export type Status = '待规划' | '进行中' | '审核中' | '阻塞中' | '已完成'

export interface HistoryEvent {
  id: string
  at: string          // ISO 8601
  from: Status | null // 创建为 null
  to: Status
  result: 'success' | 'rejected'
  reason: string      // 非空；拒绝时必须解释允许目标
  actor: string       // 固定“示例用户”
}

export type EvidenceKind = 'sample' | 'real' | 'pending'
export type EvidenceType = 'note' | 'doc' | 'test' | 'pr' | 'screenshot'

export interface Evidence {
  id: string
  title: string
  kind: EvidenceKind
  type: EvidenceType
  status: string
  detail: string
}

export interface WorkItem {
  id: string
  type: WorkItemType
  title: string
  description: string
  priority: Priority
  assignee: string
  acceptance: string
  status: Status
  createdAt: string
  updatedAt: string
  history: HistoryEvent[]
  evidence: Evidence[]
  [extra: string]: unknown // 未知字段保留
}

export interface BoardState {
  version: 1
  items: WorkItem[]
  updatedAt: string
  [extra: string]: unknown // 未知顶层字段保留
}
```

- 所有时间使用 `new Date().toISOString()`，展示时按浏览器本地时区格式化。
- 历史事件 `id` 使用现有 `uid()` 或等价唯一 ID；不得依赖数组下标。
- 证据 `type: 'pr'` 仅允许用于真实存在的 PR；本轮不存在 PR，种子与新建证据不得使用该类型。

## 6.2 状态机

| 当前 \ 目标 | 待规划 | 进行中 | 审核中 | 阻塞中 | 已完成 |
| --- | --- | --- | --- | --- | --- |
| 待规划 | 拒绝 | 允许 | 拒绝 | 拒绝 | 拒绝 |
| 进行中 | 拒绝 | 拒绝 | 允许 | 允许 | 拒绝 |
| 审核中 | 拒绝 | 允许 | 拒绝 | 拒绝 | 允许 |
| 阻塞中 | 拒绝 | 允许 | 拒绝 | 拒绝 | 拒绝 |
| 已完成 | 拒绝 | 拒绝 | 拒绝 | 拒绝 | 拒绝 |

- `canTransition(from, to)` 仅在上表为“允许”时返回 `true`。
- 拒绝原因模板：
  - 已完成：`已完成工作项只读，不允许任何状态流转，也不会自动重开。`
  - 其他：`不允许从「{from}」直接流转到「{to}」。允许的目标状态：{allowed.join('、')}。`
- 拒绝事件写入历史，`from`/`to` 为目标与当前状态，`result: 'rejected'`；工作项 `status` 不变，`updatedAt` 更新。
- 新建工作项固定从 `待规划` 开始，表单不提供初始状态。

## 6.3 存储契约

```ts
type LoadMode = 'ok' | 'empty' | 'corrupt' | 'unavailable'

interface LoadResult {
  mode: LoadMode
  state: BoardState        // corrupt/unavailable 时为种子，仅内存
  raw: string | null       // corrupt 时保留原始字符串
  reason: string           // 用户可读原因
}

interface SaveResult {
  ok: boolean
  mode: 'ok' | 'write-error' | 'blocked-corrupt'
  reason: string
}
```

- `loadBoard(storage)` 必须捕获 `getItem` 异常；`saveBoard(storage, state)` 必须捕获 `setItem` 异常。
- `corrupt` 模式下保存默认被阻断，直到用户显式覆盖；`reset` 的确认动作视为显式覆盖本应用 key。
- `unavailable` 模式不阻断内存操作，只提示刷新后丢失。
- 读取合法数据时保留未知字段；保存时不得丢弃。
- 不实现跨标签页同步；最后写入者获胜，作为已知限制记录。

# 7. 非功能要求
